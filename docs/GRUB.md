# GRUB and snapshots

Normal Debian boot must remain usable without a GRUB username/password. First boot generates a PBKDF2 hash locally with `grub-mkpasswd-pbkdf2`; neither plaintext nor hash is in Git/CI/ISO. `/etc/grub.d/01_workstation_users` defines the superuser.

During FAI, the bootloader disk is selected separately but split OS/bootloader arrangements are rejected. The partition hook writes `BOOT_DEVICE` and `PHYSICAL_BOOT_DEVICES`; the GRUB script requires both to match the persisted boot target and verifies that the mounted ESP is physically backed by that same disk before running `grub-install`.

`update-grub-secure` runs Debian `update-grub`, marks exactly one normal top-level Debian entry `--unrestricted`, and rejects any unrestricted recovery, advanced, firmware, or snapshot entry. Editing (`e`) and the GRUB command shell (`c`) require the superuser. Snapshot entries generated by grub-btrfs remain restricted. `grub-security-check` verifies this invariant.

The ISO build vendors pinned grub-btrfs v4.14 source after checking its release commit prefix. If the source was not built into the config space, FAI leaves snapshot-menu integration absent rather than silently fetching unpinned code. A systemd path reapplies the authentication policy when `grub-btrfs.cfg` changes.

Constraints: Debian GRUB 2.12 can unlock LUKS2 only through PBKDF2 keyslots, so both bootstrap and permanent slots use PBKDF2. Snapshot boot is a recovery aid, not an automatic rollback guarantee. Writable services, the separate `@home`, firmware state, EFI files, and bootloader updates are outside a root snapshot. Validate a snapshot, then perform an explicit rescue rollback if needed.
